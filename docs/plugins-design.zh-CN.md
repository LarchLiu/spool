# Spool 插件系统设计

状态：设计草案，尚未实现。文中的命令、文件格式和协议均为提案。

## 1. 目标与范围

让服务主机管理员按需安装、配置、启用、更新、停用和卸载官方插件。新安装不依赖任何可选插件即可使用本机工作区；不需要 Relay、Tailscale、远程桌面、手机共享或第三方登录的用户不必安装它们。没有 Agent 后端时仍能管理工作区、浏览文件和查看已保存的聊天，只是不能发起 Agent 任务。

**统一安装、设置和生命周期，不统一所有业务协议。** 插件可以是随包分发的子进程、Spool 已支持的外部 helper，或由主程序执行的声明式资源。迁移期允许内置适配器使用同一管理入口，但界面明确标注「内置」，不把开关伪装成卸载，也不要求每个小功能额外启动一个进程。

不做第三方市场、任意安装脚本、Go 动态库加载、运行时注入客户端代码，也不把同一 OS 用户下的子进程当作安全沙箱。Web/PWA 和 Android 消费服务器公布的能力，不下载或运行服务端插件。Android 内嵌传输和本机系统能力仍由 APK 管理。

## 2. 插件清单与核心边界

| 插件类型 | 可选组件 | 插件负责 | Spool 核心保留 |
| --- | --- | --- | --- |
| 远程入口 `ingress` | Relay 主机连接器、Tailscale `tsnet` | 网络接入、协议握手及连接状态 | 可信入口注册、HTTP 路由、登录、来源与 CSRF 校验、设备配对和授权 |
| 主机扩展 `host-integration` | Voxl、ADB Bridge | 远程桌面 helper 或设备传输桥 | 用户授权、客户端 API、连接的归属与撤销 |
| 消息渠道 `channel` | Telegram；后续飞书 / Lark、Discord、Slack | 平台协议、收发、平台确认和格式化 | 成员绑定和 Route、会话及任务、审批、持久去重和 Outbox、外发策略 |
| Agent 后端 `agent` | Codex、Claude Code 接入适配器；之后才接更多后端 | CLI 探测、模型目录、原生会话、流式事件转换及执行控制 | 项目授权、会话与队列、审批决定和审计、跨端同步 |
| 身份提供方 `identity` | 通用 OIDC（先用 Google 验证）、GitHub OAuth | 供应商协议与外部身份解析 | 回调事务、成员及身份绑定、会话/Cookie 签发和撤销 |
| 文件预览 `preview` | Word / Excel 优先；再评估 PDF 文本提取、EPUB 等 | 只读解析，输出结构化预览 | 文件访问、下载、限额、客户端渲染与降级 |
| 自动化来源 `automation-source` | GitHub Issues；后续 GitLab Issues、Jira 等 | 查询来源数据、映射任务、回写外部结果 | 调度、持久认领和去重、项目权限、执行与审计 |
| 通知出口 `notification-sink` | 单向 IM 通知；有需求再做邮件或 webhook | 把获准的通知投递到指定目标 | 未读与通知偏好、订阅和授权、投递记录及重试策略 |

上表是候选目录，不代表首版全部拆包。普通 Web/HTTPS 入口、本机管理与恢复、People/Projects、文件权限、聊天及任务状态、数据库与租约、更新验证和客户端渲染基础设施均留在核心。插件之间不直接访问对方数据库、凭证或私有进程；例如 Telegram 通过核心的任务用例调用已授权的 Agent，不依赖某个 Agent 插件，也不要求装 Relay。

## 3. 插件宿主

### 3.1 包、目录与版本

- 官方目录提供包 ID、显示名、发行版本、适用的 OS/架构及是否内置。包包含 `plugin.json`、可选的 `settings.schema.json` 和语言资源，以及对应平台的二进制或其他资源。Manifest 声明稳定 ID（例如 `spool.channel.telegram`）、类型、执行方式、入口、宿主兼容范围、协议主版本和设置版本。包版本、协议版本与设置版本独立；Agent 后端 ID、身份连接 ID 等业务标识不使用包版本或文件名。
- 按主机的 `<data-dir>` 隔离安装目录、可变状态和私有凭证。SQLite 由核心独占，子进程不接收数据库连接、所有用户的凭证或通用管理令牌。日志、状态、配置导出和客户端能力响应不回显密钥；只有获准的适配器取得该实例所需凭证。
- 复用[现有签名更新](../internal/appupdate/manifest.go)的信任原则：校验签名、目标平台、版本、包摘要及文件边界后才允许执行；拒绝路径越界、链接跳转和归档超限。下载并解包到暂存目录，验证后原子切换活动版本。仅在旧包与现有配置仍兼容时回滚；不可逆配置迁移不得静默覆盖旧配置。现有 Voxl 的本机手动导入是明确的管理员操作，不作为下载签名校验的例外通道。

以下以 Linux/amd64 的 Telegram 外置包说明交付边界；每个目标平台发布自己的包，配置和连接记录不随包分发。

```json
{
  "manifestVersion": 1,
  "id": "spool.channel.telegram",
  "kind": "channel",
  "version": "1.0.0",
  "target": "linux-amd64",
  "minHostVersion": "1.0.0",
  "runtime": {
    "mode": "subprocess",
    "entrypoint": "bin/spool-channel-telegram",
    "protocolVersion": 1
  },
  "settings": { "path": "settings.schema.json", "schemaVersion": 1 }
}
```

### 3.2 启停与通信

- 管理器区分**安装版本、配置是否完整、期望启用状态、实际运行状态**。安装不自动启用、不授权、不开始屏幕采集或设备共享。启用后视类型常驻（Relay、Tailscale、已配置的 Channel），或按需启动（Agent、Voxl、文件预览）；内置 OIDC 不需要额外进程。
- 受管子进程使用本机私有 IPC，首版可用 `stdin/stdout` 上的带请求 ID、帧大小上限和超时的消息做握手、控制和状态，`stderr` 用于经过过滤的诊断。握手校验插件 ID、协议与所需能力；不兼容则拒绝启动。ADB、远程桌面和入口代理的大流量走专用本地数据通道，使用私有端点或受限制的临时凭证。远程入口的可信来源由宿主按已授权连接绑定，不能取信于远端请求头，也不暴露本机管理接口。不提供任意注册路由、通用 RPC 或前端到子进程的直通接口。
- `workspace.Service` 持有插件宿主并负责生命周期。沿用[运行租约](../internal/workspace/runtime.go)：管理模式只读状态或修改配置，不开启长驻接收器；丢失租约立即停止领取新工作和接收新请求。停用先禁止新请求，再按插件类别关闭连接、撤销待投递资格或等当前任务结束，最后取消、等待并回收所属进程及子进程；在关闭 Store 前完成回收。单个插件故障只降级该能力，退出原因可见，重启需退避；不会因连接器或通知插件失败而取消现有聊天。
- 更新默认不抢占共享 App。Agent 适配器等待现有任务结束后切换；异常退出时影响其运行中的任务，核心记录中断，不自动重跑。入口更新可重连，但不关停本机管理入口。停用/卸载与清除配置、凭证、外部注册及配对是不同操作：可保留配置用于重装，但停用期间不得继续使用；敏感数据清除或远端注销需要明确动作。已撤销的授权和待处理外发请求不因重装而复活。
- 进程隔离主要处理故障与独立发布。限制环境变量、传递的数据和 IPC 能力，不能阻止同一 OS 用户下的恶意进程访问该用户可读的文件；不能信任的解析器或第三方执行器需要另行设计可验证的文件、网络和进程隔离，不在首版开放。

### 3.3 入口与兼容

Desktop 增加固定的「插件」入口，用于浏览、安装和诊断；Agents、成员、服务等已有位置继续承载对应业务，也可以链接到插件配置。headless 提供等价的本机管理命令（例如 `spool-server plugins list|install|enable|disable|update|remove`），沿用现有[本机管理](server-cli.md#local-administration)的权限与租约约束，不为首版增加公开管理 API。客户端从服务端取得当前连接/账号可用的能力；只有同时满足服务可用、用户授权和客户端支持时才显示功能入口。登录页匿名获取当前可信入口允许的登录方式，不返回私有配置。服务端对每次实际请求仍独立校验。

对现有安装按能力逐项迁移。旧配置缺失或外置包尚未装好时保留原适配器；仅在目标版本和配置准备好后才切换，避免覆盖远程入口、配对、节点身份或会话标识。旧客户端在迁移期沿用既有 API；如确实需要升级客户端，应先给出状态和可用的本机恢复路径。新安装默认不启用外部入口、身份提供方或外发通知。

## 4. 声明式设置

插件声明需要哪些字段和操作，Spool 决定展现与授权。描述文件随安装包分发，读取设置不需要启动插件；插件崩溃也能打开设置修复。现有 [Desktop 设置宿主](../web/src/settings-app.tsx)和[表单控件](../web/src/settings-ui.tsx)可作为渲染入口。示例：

```json
{
  "schemaVersion": 1,
  "title": "Telegram Bot",
  "fields": [
    { "key": "botToken", "type": "secret", "label": "Bot Token", "required": true },
    { "key": "pollTimeoutSeconds", "type": "integer", "label": "长轮询超时（秒）", "default": 30, "min": 5, "max": 60 }
  ],
  "actions": [
    { "id": "testConnection", "label": "测试连接" }
  ]
}
```

- 首版支持开关、文本、整数、枚举、密钥，以及经过宿主控制的路径选择；插件可提供本地化文案，字段和操作 ID 不随语言改变。设置版本不兼容或字段类型未知时报告兼容错误，不生成可提交的表单，也不破坏旧值。
- 后端按插件实例命名空间保存，重复校验类型、必填、范围和调用人权限。密钥只显示「已配置」，替换、清除和不修改是不同操作。默认不允许插件动态注入 HTML、JavaScript、iframe、脚本式校验或任意表单提交 URL。
- 按钮是已声明的操作 ID，不是 Shell 命令。宿主决定谁能调用、是否允许临时启动诊断进程、超时和结果展示。例如 Telegram「测试连接」可以调用 `getMe`，不消费更新、不改变启用状态。模型目录、运行状态、诊断等是受控的运行时数据，不修改静态设置定义。
- 配对、审批、成员/项目授权、身份绑定等使用核心页面和核心接口。插件可提供跳转，但不能以自定义表单替换授权流程。二维码、分页或状态标签有共同需求时，由主程序增加受控组件。

## 5. 已讨论组件的拆分

### 5.1 Relay、Tailscale、Voxl、ADB

- **Relay**：VPS 上的 [`spool-relay`](../relay/README.md) 已独立部署，不归主机插件宿主管理。仅拆 Spool 主机连接器，保留注册身份、设备配对与撤销、LAN 优先、可选 Web/PWA 和现有 TLS 信任边界。Web Relay 与 Android 端到端传输不是同一信任模型。当前启动 Relay 失败可能使整个服务启动失败（[运行时](../internal/workspace/runtime.go)），先解除这个耦合再拆包；本机远程变更继续使用可回滚的独立入口切换，而非重启 App。
- **Tailscale**：主机的[内嵌 `tsnet`](../internal/workspace/tailnet.go)负责 tailnet 节点状态及 HTTPS 入口；不把网络成员身份当作 Spool 用户。迁移保留节点状态，不要求重新加入 tailnet。已运行系统 Tailscale 的人可通过相应网络访问普通 Spool HTTPS，不必安装内嵌连接器。Android 自带 `tsnet` 的构建与分发是独立问题。
- **Voxl**：复用[现有 helper 管理](../cmd/server/cli_voxl.go)和平台权限处理，包括 macOS `Voxl Helper.app` 的系统授权。无需再包一层常驻代理；仅在获授权的查看/传输需要时启动，停止后等待采集退出。提供插件 UI 后，先沿用现有安装方式，再评估官方预构建分发及可省去的发行包依赖。
- **ADB Bridge**：拆 [Spool 手机共享桥](adb-bridge.md)，不把 Android SDK Platform-Tools 当作 Spool 自带插件。WebUSB 和 Android 无线调试前台服务保留在客户端，经现有授权流连接主机 `adb`；停用、退出或撤权时断开设备。主机同一 OS 用户下其他进程也能访问共享设备，项目权限不构成设备隔离。

### 5.2 Channels

[Channels 设计](channels-design.zh-CN.md)继续定义配对、跨端 `steer`、审批、任务恢复和出站语义。该草案的「内置 Channel Runtime」保持不变：共享用例、持久化和投递调度都在 Spool 主机内，不另起 Bot 服务。先用假适配器和 Telegram 验证核心行为；Telegram 可先是内置适配器，边界稳定后单独发布，飞书等新增平台按相同边界接入。

外置适配器只收发、规范化平台数据，不能替 Bot 用户直接启动 CLI 或以管理员身份调用。平台确认必须等待核心持久受理，外置进程不自行推进 Telegram 游标或抢先确认；推送前仍由核心复核授权和目标代次。停用适配器不把已有任务重跑，也不将未获准的内容改投到其他渠道。通知出口只做单向提醒，不获得 Channels 的会话写入或审批能力。

### 5.3 Agent 后端

把 **CLI 接入适配器**做成插件，不重分发现有 CLI，不接管其供应商登录。用户可以继续使用已安装的 `codex` 或 `claude`，由适配器探测健康、模型和实测能力，并映射启动/恢复、流式事件、停止、`steer`、审批请求和原生历史。Web、Desktop、Android 依据已注册的后端和真实能力显示界面，而不是插件自己画聊天界面。

先在进程内统一注册，再实现调用外部进程的版本化适配器。[`AgentRunner` 与 `AgentEvent`](../internal/agent/runner.go)是起点，不直接把 Go 接口作为 IPC 协议；当前[注册表](../internal/workspace/registry.go)、[权限模式](../internal/model/permissions.go)与 [Web 后端类型](../web/src/types.ts)还内置了两种后端假设。保留已有 `codex` / `claude` ID 与原生会话关联。项目规定的权限模式无法可靠落实时拒绝启动，不能只信插件的能力声明或静默降级。

卸载不删除 Spool 的聊天记录或 provider 原生历史。当前[历史有部分从原生格式读取](agent-session-history.md)，所以外置前必须验证历史降级：关键路径至少保留现成可读的结构化记录，或在迁移期保留只读兼容解析；缺少原生记录的会话须明确提示不可用。重新安装兼容适配器且原生会话仍在时可以继续，不自动换后端。

### 5.4 成员与 OAuth/OIDC

首版的 Google（通用 OIDC）和 GitHub（专用 OAuth 适配器）作为内置官方适配器，管理员可独立启用。它们可以共享设置和能力注册，但没有理由各自暴露监听端口或单独签发会话。登录页动态公布当前入口可用的方式；成员页管理绑定和撤销；密码和本机管理路径保留，防止第三方不可用时锁死实例。

- **只绑定已有成员，不开放自动注册。** 用户先用现有方式登录，再主动绑定。Google 用已验证的 `issuer + sub`；GitHub 用受信任 GitHub API 返回的稳定用户 ID，按提供方/实例区分。不按邮箱、用户名或昵称自动合并；外部主体同一时刻只能绑定一个本地成员，禁用成员不可签发新会话。
- 核心持有短时、一次性的登录/绑定事务，绑定浏览器、提供方、操作、精确回调和允许的返回目标，使用 `state`、PKCE `S256`，OIDC 另校验 `nonce`、签名、签发方、受众和时效。回调只接受预注册入口，不从不可信 Host 推导，不接受任意返回 URL。把回调单独处理为预期的跨站跳转，不放宽现有密码登录和其他写操作的同源/CSRF 校验。[现有密码登录和会话逻辑](../internal/workspace/auth.go)可抽出共用的会话签发入口。
- 会话记录签发来源，以便解绑撤销对应账号的第三方会话、停用提供方撤销该提供方的会话；密码会话不受影响。渠道配对、Relay 设备身份与 OAuth 网站登录的用途不同，不能互相替代或自动晋升为成员权限。
- 先做 Web/PWA，回调地址必须能由用户浏览器访问并满足供应商的注册要求，不必一律开放公网。Android 原生随后用系统浏览器和一次性会话交接，不把供应商 Token 塞进应用跳转 URL；在此之前不能移除现有客户端可用的登录方式。通过 Relay Web 使用时，明确保留其信任提示，不把该入口默认当成第三方登录回调。

## 6. 文件格式解析与显示

**首版插件化服务端解析，允许插件选择预览结果类型，不允许插件携带渲染代码。** 这是最贴近现有架构的拆法：[Office 预览](office-preview.md)已经在 Go 端解析 `.docx` / `.xlsx` 并返回结构化 JSON，由 Web、Desktop 和 Android 各自渲染。先在现有 `office=1` 路径后注册 `office-docx`、`office-xlsx` 两个内置解析器，保持现有接口和共享测试 fixture，再验证同类型的可选解析包。

1. **选择解析器。** 插件声明支持的 MIME、扩展名、探测规则和输出类型。Spool 根据可信元数据和受限的文件头/容器探测进行匹配，不仅凭扩展名；冲突先沿用受信任内置实现，替换需管理员明确选择。插件不能截获通用文件路由。
2. **传入已授权内容。** 核心仍按项目、会话、worktree 和外部文件规则打开文件，只向解析器传有界字节流或隔离的单文件句柄，不让其按用户提交的路径读文件。每次请求处理超时、取消、输入/输出、展开体积、文档块和分页上限；禁止执行宏、重新计算公式、加载外链资源或上传文件到外部转换服务。若要运行可读不可信文件的外置解析器，先落实相应的 OS 级限制，不把 IPC 当成隔离。
3. **返回可安全渲染的结构。** 先复用文档块和分页表格；以后可加纯文本、受限图片或页面图像等明确类型。宿主校验结果版本、尺寸、资源引用和结构，客户端用已有组件渲染，不接受解析器的 HTML、脚本、任意 URL 或 WebView 页面。使用已有输出类型的新格式通常不用发新版客户端；若要新增渲染器类型，应先升级相应客户端，不能靠插件下发客户端代码。
4. **保留降级与原件。** 缺插件、版本不兼容、格式不支持、文件加密或解析超限时，保留原文件下载；安全且适合的内容可退回纯文本。预览失败不能影响项目文件列表、聊天、附件读取或下载。原始内容与预览缓存按文件版本区分；缓存不得跳过每次读权限检查。

PDF 在 Web 和 Android 已有客户端预览，基础预览继续内置；确有需求时再用插件增加服务端文本提取或页缩略图。Markdown、纯文本、基础图片和 Diff 是聊天/文件的通用体验，保留内置渲染。额外的语言语法包可以是声明式资源，但不是文件解析插件的首版要求。

## 7. 额外可拆候选与取舍

| 候选 | 建议 |
| --- | --- |
| GitHub Issues 自动化 | **优先纳入设计，晚于首个插件落地。** [Issues 调度](../internal/workspace/issues_scheduler.go)、认领、旧台账兼容、worktree 和执行审计留核心。将任务来源和结果发布视为可独立的能力，例如 Jira 工单仍可产出 GitHub PR；先保持当前行为，不为尚未接入的平台预造统一写回 API。外部任务按来源实例与外部 ID 区分；项目自动化凭证与 GitHub 登录凭证各自授权。 |
| 单向通知出口 | **值得保留独立类型。** 会话未读、收件人复验和通知过期规则留核心；[Web Push](../internal/workspace/web_push.go)和系统弹窗可作为内置适配器，不急于拆包。邮件或 IM 只接收明确允许的数据，不订阅任意事件，也不默认转发聊天正文、工具日志或审批细节；不放宽现有出站地址校验。 |
| 扩展文件语法、主题、头像样式 | 可做低权限的声明式资源包，复用分发而非进程宿主；基本语言、可访问性、默认头像和渲染仍由客户端负责，优先级低。 |
| Git 平台集成、导入导出 | 有第二个真实平台或格式时再抽取远端元数据、外部导入等适配器。通用 Git/worktree 操作、项目路径和授权、核心数据备份/恢复不移出核心；原生 Agent 会话格式优先由各自 Agent 适配器管理。 |

## 8. 实施顺序与验收

1. **宿主最小闭环：Voxl。** 统一注册、静态设置、状态、启停和本机管理；用假子进程测握手、超时、退出清理及错误隔离，Voxl 验证已有 helper 无需重写。签名目录和更新回滚在分发新可执行包前就要可用。
2. **并行验证三类边界。** Channels 做共享用例、假适配器和 Telegram；Agent 注册把现有两个后端改成内置适配器并用一个外部 fixture 验证协议；预览注册接入现有 Word/Excel，保持跨端结构兼容。不要让这三项等到 Relay/Tailscale 拆包才开始。OAuth/OIDC 在同一管理界面实现 Web/PWA 的绑定、登录和撤销。
3. **逐项外置。** 先发布第一个官方外置适配器并验证安装、更新和回滚，再逐步迁移 ADB、Tailscale，最后 Relay；只有当兼容升级得到验证，才从对应核心发行包或安装依赖中移除旧实现。通知出口、其它格式和自动化来源按需求落地。

各阶段按所交付的插件验证以下行为：

- 没装插件仍可启动、登录和管理核心工作区；装上后设置自动出现，停用或崩溃时仍可编辑。安装不自动授权。命令行与 Desktop 看到一致的状态，Web/Android 只在当前账号和服务器具备能力时显示入口。
- 拒绝无效签名、不兼容包和不合法设置；宿主接口不允许插件读取其他插件的凭证。升级失败可安全恢复或明确提示需要人工处理。停止或丢失租约后没有残留进程、接收器或重复消费者。
- Relay 或 Tailscale 故障不退出本机服务；迁移不丢失已验证的配对、节点身份及原生会话关联。停用 Agent 不影响已保存聊天，停用 ADB/Voxl 撤销正在使用的设备/桌面入口。
- OAuth 不因相同邮箱合并账号、禁用后不能新登录、撤销对应第三方会话且不影响密码登录；Channels 停止收发不触发 Agent 重跑。
- 对同一份 Word/Excel 授权文件，Web/Android 共用结构化结果，禁用解析器后仍可下载；越权文件、超限内容、崩溃或未知输出类型不会读出不应访问的文件，也不会把活动内容注入客户端。
