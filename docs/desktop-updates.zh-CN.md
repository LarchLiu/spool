# 桌面自动更新

[English](desktop-updates.md)

官方桌面版从 GitHub 稳定版发布源检查更新。Spool 使用 Ed25519 公钥验证收到的
清单原始字节，再由 MyGo 验证压缩包签名，验证通过后才解压、安装。签名错误会
终止更新。开发版不启用自动更新；安装位置需要可写，包管理器安装的应用应通过
包管理器更新。

自动安装继续使用现有的运行中会话检查和更新锁。下载、安装、重启仍是独立状态。
macOS 上 MyGo 0.10 先把新应用包暂存在安装位置旁，进程退出后才替换旧包。
“已安装”表示更新已准备好，正在运行的进程要重启后才使用新版。Windows 和
Linux 使用 `.mygo-files` 记录应用拥有的文件；后续更新删除废弃的应用文件，
保留未列入清单的便携数据和卸载器等文件。macOS 用户数据应放在 `.app` 包外。

## 版本衔接与发布约束

MyGo 0.6.4 的升级器可以安装包含 MyGo 0.10 的新版本。新版本启动后，下一次
更新就由新升级器执行。无需另发一个过渡版本；只要以下协议继续兼容，用户也
可以跳过中间的 Spool 版本直接升级：

- 保留现有更新签名密钥和 `spool-update-v1` 清单结构。
- 为每个目标平台发布 `update-OS-ARCH.json`、其独立 `.json.sig` 签名，以及
  `spool-VERSION-OS-ARCH.tar.gz`。
- 打包结束后对最终压缩包和清单字节签名，并保持版本一致。必须递增 **Spool**
  版本号；只更新 MyGo 依赖不会向相同 Spool 版本的客户端提供更新。
- 保留两代升级器都能识别的 tar 包结构。DMG 和 Windows 安装器的文件名不决定
  自动更新压缩包的下载地址。

Spool 已通过 `Updater.SetSource` 接入经过签名验证的更新源，替代旧的全局 HTTP
客户端拦截方式。新版 MyGo 的专用客户端会绕过旧拦截，因此这一适配是必要的。
新更新源保留 Spool 动态代理配置，并且只允许访问已验证清单中的压缩包地址和大小。

MyGo 还支持预发布选择和差分更新。Spool 当前继续使用稳定版完整包；开启这两项
需要另行适配签名发布源、清单验证和发布流水线。新安装和重启机制不依赖这两项。

## 回归验证

`internal/appupdate` 的常规测试实际编译 MyGo 0.6.4 和 0.10.0 发布模式程序，
验证旧到新、新到新的安装，以及下载中断、取消时保留原程序和用户文件。
旧版测试通过临时独立 modfile 编译，不修改项目依赖版本或替换可复用缓存。

原生重启测试进一步验证单实例锁、退出清理，以及重新启动的程序版本：

```sh
sh tools/run.sh updater-e2e sh -eu -c '
  SPOOL_UPDATER_E2E=1 go test -v -timeout=5m ./internal/appupdate \
    -run "^TestMyGoUpgradeReplacesApplicationAndPreservesUserData$"
'
```

构建和发布 CI 为每个原生系统／架构执行该测试。Linux 需要图形显示环境，CI 通过
Xvfb 和 D-Bus 会话提供。这些测试覆盖真实升级器与生命周期 API，不等同于完整
历史版本 Spool 或实际已发布资源的下载测试。
