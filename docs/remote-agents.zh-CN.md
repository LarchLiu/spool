# 跨服务器 Agent 调用

Spool 支持用户直接将任务发送到互信服务器，也支持本地 Agent 通过内置 MCP 委托远端 Agent。两条入口使用相同的远端任务与权限检查。

## 配置与目标发现

先按照[服务器互信指南](server-federation-design.zh-CN.md)配置 A → B 的信任方向，在 A 放行所需用户，在 B 开启接收并设置首次加入的默认项目。双方需要可用的控制线路：A 向 B 提交请求，B 回连 A 核验一次性凭据。HTTPS、Tailscale 和 Relay 均复用既有签名控制通道。

A 查询的是**当前登录用户在 B 有权访问的项目**，包含项目名称、说明和能否创建会话。首次访问按 B 的配置建立外部账号及默认项目成员关系；之后以 B 当前的成员权限为准。不会获取 B 的完整用户目录、项目成员表或项目文件路径。

选择项目后可以发现 B 的 Agent 安装状态、版本、说明、模型 ID、提供方说明、维护的模型说明、默认模型和推理强度。说明在 B 的[项目与 Agent 设置](descriptions.zh-CN.md)中维护。提交任务时再次验证模型、推理强度及项目权限。

## 用户使用 `@`

在消息输入框中输入 `@`，与 `/` 菜单类似，弹出互信服务器列表。服务器行右侧的 `>` 表示可进入该服务器的项目列表。支持输入筛选、上下键选择、Enter/Tab 确认、左方向键返回和 Escape 关闭。

只读项目保留在列表中并标记“只读”，置灰且不能通过点击或键盘选中。续接已有调用时也会刷新项目权限；权限变为只读后不能继续对话，仍可按现有查看权限读取结果和历史。

选中项目后，输入框显示独立的 `@服务器/项目` 目标标签。它是发送元数据，不属于消息正文。正文中用于选择目标的 `@` 输入片段会被移除，已有任务文字会保留。Agent、模型及推理强度选择器使用目标服务器的目录。

点击正常的发送按钮，将正文直接提交给远端 Agent。这个动作不启动本地 Agent，也不调用 MCP 工具。新建的本地聊天会先保存为调用记录的父会话。当前入口支持文本，远端沿用目标项目默认权限模式。MCP 委托同样只使用该默认模式，模型不能自行选择。

以 `/` 开头的原生命令交给目标 Agent 执行，例如 `/review`、`/goal`、`/goal clear`。命令的支持范围和参数由目标 Agent 决定，结果通过远端任务返回；不支持的命令返回失败。命令不接受独立的 `context` 字段，以免追加的参考资料改变命令参数。续接已有会话时可调整同一 Agent 的模型和推理强度；切换 Agent 需先选择“新建远端会话”。

浏览器 Web 和桌面内嵌 Web 使用同一套流程，无需桌面桥接。调用记录与 Android 一样，在输入框上方显示“跨服 Agent · 调用数量 · 最新状态”入口，点击后打开最近调用列表，再选择一条进入详情。详情显示 Agent、模型、推理强度、任务状态、任务正文和运行中的最新回复；回复和远端历史使用 Markdown 显示。用户可以停止任务、处理远端审批、续接同一远端会话、分页查看历史，或把**已完成任务的最终回答**作为参考上下文加入本地草稿。“用结果作为上下文”会清除远端发送目标，便于把草稿交给本地 Agent；续接或导入结果后会关闭弹窗并回到输入框。运行、失败、停止或中断的输出不能通过此按钮导入。切换本地会话或账号会关闭记录弹窗，并清空上一个会话的目标选择。

Android 使用原生输入框弹窗提供同样的 `@ → 服务器 > → 项目` 选择，沿用目标服务器的 Agent、模型、推理选项和说明。输入框上方的跨服调用入口可查看任务、Markdown 结果、人工审批、分页历史，并停止或续接会话。调用结果只有完成后才能加入本地草稿。进入后台暂停查询，返回前台恢复；切换账号、服务器或聊天会清空目标，过期请求的响应不会恢复旧选择。

## Agent 使用 MCP

在输入框输入 `/`，选择右侧带 `>` 的 `mcp` 行，进入 MCP 列表；也可直接输入 `/mcp`。列表当前提供“跨服 Agent”（`spool_federation`），没有可用互信目标时该项不可选。支持键盘 Enter/Tab/右方向键选择、左方向键返回和 Escape 关闭。

MCP 子菜单按目录逐项显示，目前只内置上述一种。每个 MCP 独立选择、取消及移除标签；支持筛选和上下方向键切换列表项，新增 MCP 后会沿用同一列表及选择流程。

**默认不注入任何 Spool MCP**。选择后输入框显示独立的 MCP 标签，`/mcp` 是界面操作，不会成为消息正文或发给原生 CLI 的命令。选择仅属于当前聊天，发送时通过 `mcp_servers` 元数据携带；同一聊天后续消息保留选择，移除标签后后续回合不再注入。新建/切换会话、切换账号或刷新页面默认清空，不保存账号总开关。Web 和桌面使用同一流程；用户直接 `@服务器/项目` 无需选择 MCP。

Android 也提供原生 `/ → mcp > → 跨服 Agent` 菜单和可移除的 MCP 标签，没有互信服务器时该 MCP 置灰不可选。普通消息、排队消息及附件上传均携带独立的选择元数据。App 重启后默认不选；主题或屏幕方向变化保留当前聊天的选择。通过 MCP 创建的任务会出现在同一跨服调用面板中。

只有消息明确选择该 MCP，且同时满足本服登录用户、当前父会话控制权、至少一个可用的互信目标，才会在正常聊天消息回合中注入。描述总结、后台自动任务及从远端委托过来的 Agent 不接入。选择或移除在回合开始时生效，不对运行中的回合动态增删工具；已经提交到 B 的任务可通过调用记录停止。

注入仅作用于 Spool 启动的进程/会话，不执行 MCP 注册命令，也不修改用户或项目的原有 Agent 配置：

- Codex：通过 app-server `thread/start` / `thread/resume` 的 `config` 参数传入本次会话覆盖值；授权头从该子进程的环境变量读取。
- Claude：通过 `--mcp-config` 加载 Spool 在系统临时目录创建的独立 `mcp.json`，文件权限为 `0600`，所在临时目录为 `0700`；进程结束时删除。普通聊天不加 `--strict-mcp-config`，保留用户原有 MCP 的加载规则。

不会写入 `~/.codex/config.toml`、Claude 用户配置、项目 `.mcp.json` 或 `.claude/settings*.json`。每个回合使用独立随机凭据，回合结束失效；切换凭据或关闭注入后，后续回合会重启受影响的 CLI 进程并续接原生会话。

| 工具 | 用途 | 主要参数 |
| --- | --- | --- |
| `spool_servers` | 当前用户可用的互信目标 | 无 |
| `spool_projects` | 目标服务器上的授权项目与说明 | `server` |
| `spool_agents` | 项目的 Agent、模型、说明与推理选项 | `server`, `project` |
| `spool_permissions` | 目标项目中 Agent 的原生权限模式与项目默认值（仅供了解，不能更改） | `server`, `project`, `agent` |
| `spool_delegate` | 提交新任务或续接远端会话 | `server`, `project`, `agent`, `message`, `request_id` |
| `spool_task` | 获取状态，完成后获取最终回答；审批仅返回需人工处理的标志 | `server`, `task_id` |
| `spool_cancel` | 请求停止任务 | `server`, `task_id` |
| `spool_conversations` | 本父会话委托过的远端会话 | `server`，可选 `project`, `before`, `limit` |
| `spool_history` | 按需读取远端文本历史 | `server`, `conversation_id`，可选 `before`, `limit` |
| `spool_calls` | 恢复本地保存的最近调用引用与结果摘要 | 无 |

`server`、`project` 和 `model` 使用发现接口返回的 ID。`agent` 为 `codex` 或 `claude`。
`spool_delegate` 还支持 `model`、`reasoning_effort`、`context`、`conversation_id` 和 `wait_seconds`。省略模型时使用目标 CLI 默认值。权限模式不是工具参数：委托任务始终按目标项目的默认模式运行，避免模型自行选用免审批模式；传入 `permission_mode` 会被拒绝。

B 未能确认委托（例如回复在途中丢失）时，A 用同一个 `request_id` 自动重试一次；仍未确认则返回带该 `request_id` 的错误，调用方用它重试即可找回任务，不会重复执行。尚未开始任何回合就被拒绝的委托（例如 B 正在更新或目标会话正忙），之后可用同一个 `request_id` 重新执行。

`spool_projects` 返回的 `can_create` 同时约束新建和续接：只有 `true` 的项目能调用 Agent。B 在每次委托（包括重试和续接）时重新检查当前权限，不依赖界面禁用状态或之前的发现结果；只读项目的委托会被拒绝。

典型调用：先发现服务器、项目及模型，再委托任务：

```json
{
  "server": "<server ID>",
  "project": "<project ID>",
  "agent": "codex",
  "model": "<advertised model ID>",
  "reasoning_effort": "high",
  "message": "检查接口契约并给出修改建议",
  "context": "仅包含本任务需要的本地接口约束",
  "request_id": "<stable unique ID>",
  "wait_seconds": 20
}
```

工具返回 JSON 文本及结构化结果。`spool_delegate`、`spool_task`、`spool_cancel` 和 `spool_calls` 在未完成时只返回任务引用、状态等控制信息；仅 `completed` 的任务提供最终回答 `text` 和结果截断标志。规范化消息中明确标记的 `final_answer` 优先；旧版协议只取最后一次工具/思考之后无阶段标记的回答，不拼接此前过程说明。远端工具输入/输出、运行中的累计回复和审批表单不进入调用方工具上下文。审批只提供 `approval_required` 标志。

Web 会自动发现同一本地父会话中由 MCP 创建的调用记录，在与用户 `@` 相同的记录列表和详情中提供结果、人工审批和历史操作。运行进度通过显示用的任务 API 单独读取，不混入模型结果。原生 MCP 调用本身仍列在本地工具活动中；远端任务不是本地 CLI 创建的子 Agent。

结果属于远端参考资料，不具有 system prompt 的优先级。Spool 只发送显式给出的任务和 `context`，不会自动转发本地完整历史。`spool_history` 是 Agent 显式按需请求文本历史的独立操作，不会因委托或查询结果自动读取。

## 任务、重试与审批

委托返回持久化的 `task_id`、`conversation_id`、状态与结果。状态包括 `running`、`awaiting_approval`、`completed`、`failed`、`stopped` 和 `interrupted`。可等待最多 25 秒，之后用 `spool_task` 继续查询。

重试相同任务时保留相同的 `request_id`。B 按来源服务器、来源用户和请求 ID 去重；内容一致时恢复原任务，内容不同则拒绝。即使模型后来下线，原任务仍可在权限允许的情况下恢复。B 重启后失去运行进程的任务标记为 `interrupted`，不会自动重复执行。

远端 Agent 走 B 正常的原生执行和审批链路。`awaiting_approval` 时用户可在 A 的调用记录或 B 的聊天中处理审批。MCP 没有批准工具，不能代表用户自动确认。审批仍由 B 校验当前控制权限、原有选项与表单内容，并记录实际外部用户的审计身份。

## 历史与权限边界

完整原生对话保留在 B。A 保存任务引用、有限的已观察结果及用户任务摘要；本地会话恢复后通过 `spool_calls` 找回引用，再刷新任务或按需读取历史。

用户 `@` 和 MCP 创建的远端会话都绑定来源用户与本地父会话。续接、列举、历史和任务查询只能访问该父会话委托的远端会话，并重新检查 B 当前权限。不能借此读取该用户在 B 的其他历史。删除 B 的会话同时删除其任务记录；删除 A 的父会话清除本地调用记录，不删除 B 的原生会话。

每项操作使用新的一次性凭据，经双向签名验证和回源核验后，在 B 按普通用户权限执行。已建立且资料未变化的外部账号直接按只读方式核验，不建立登录会话；首次访问或昵称、头像变化时才走一次登录流程，产生的临时 B 登录会话在操作结束时清理。两种方式都不向 Agent 提供远端 Cookie。等待任务完成时，B 最多将一次查询保持 5 秒，A 不必反复轮询。A 退出登录、人员资格撤销、B 停用用户或移除项目权限后，后续调用会被拒绝；已经接收的任务不会因 A 浏览器退出而自动停止。

MCP 只监听本机回环地址。随机凭据按父会话和发起用户固定，常驻的 CLI 进程因此不必在每条消息后重启；凭据只在该用户在该会话的回合运行期间有效，并绑定当次的登录会话和回合，回合结束即失效，同一会话中其他用户的回合使用另一份凭据。B 的外部用户不能继续委托 C，避免可传递的身份与循环调用。

## 结果大小

任务结果最多返回 64 KiB 文本并带截断标记；本地最近 20 条调用记录各保留最多 8 KiB 的展示结果。完整内容可在 B 的原生会话中查看。

历史每页最多 8 个回合、每回合最多 8 KiB 文本，提供下一页游标和截断标记，不导出工具原始数据或附件。`context` 最多 64 KiB，任务正文与编码后的上下文合计受原有 128 KiB 消息上限约束。
